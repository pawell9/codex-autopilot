# Idea Scout

Парсер идей мини-продуктов с подтверждёнными метриками + локальный дашборд
для их отбора и запуска в работу. Один пользователь, всё крутится локально.

**Этот файл — единственный источник правды для агентов.** `CLAUDE.md` рядом
содержит одну строку-ссылку сюда. Не дублируй содержимое в него.

## Где что лежит

| Файл | Что это |
|---|---|
| `.autopilot/<дата>-idea-scout--wip/spec.md` | спецификация, редакция 2 |
| `.autopilot/<дата>-idea-scout--wip/interfaces.md` | **контракт сборки**: типы, API хранения, границы модулей, правила данных, политика тестов |
| `.autopilot/<дата>-idea-scout--wip/manifest.md` | 47 требований, что с каждым стало, и решения D01–D04 |
| `.autopilot/<дата>-idea-scout--wip/tickets/` | 17 тасков, 7 волн |
| `.autopilot/<дата>-idea-scout--wip/review-log.md` | что было найдено проверками и как решено |
| `docs/executor.md` | как исполнять таск — читается перед первой строкой кода |
| `docs/research/` | исследования: допустимость источников |

## Команды

| Команда | Что делает |
|---------|------------|
| `python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"` | установить |
| `.venv/bin/pytest -q` | тесты, автономно: без сети и без моделей |
| `.venv/bin/pytest -m real` | реальные проверки: нужны ключи и логин CLI |
| `.venv/bin/ruff check . && .venv/bin/ruff format --check .` | линт |
| `.venv/bin/idea-scout <команда>` | запуск; сейчас работает `init`, остальные числятся в справке как «появятся позже» |

Своя команда — свой файл в `src/idea_scout/commands/`: `NAME` и
`run(args, ctx) -> int`. Общий список не правится руками, справка выводится
из найденного. Заходить в зону таска 01 ради своей команды не нужно.

## Источники: что можно и чего нельзя

Паспорт до адаптера — правило без исключений. Паспорта лежат в
`docs/sources/`, читаются **до первой строки адаптера**. Исследование
допустимости — `docs/research/source-acquisition-strategy.md`.

**Охват — это композиция разрешённых каналов и классов сигналов, а не список
площадок.** Шесть классов: проблема, запуск, внедрение, внимание, деньги,
финансирование. Приёмка R10 — не меньше трёх классов из нескольких независимых
семейств каналов.

| Состав MVP (бесплатно, без ключей) | Классы сигналов |
|---|---|
| Hacker News · Algolia + Firebase | проблема, запуск |
| Product Hunt · **официальный Atom-фид**, не GraphQL | запуск |
| GitHub · REST + Search | внедрение, проблема |
| Stack Exchange · официальный API, **CC BY-SA** | проблема |
| Курируемые RSS/Atom · `config/feeds.yml` | проблема, запуск, деньги |

**Условные, по одному за раз:** Reddit, X, поисковый провайдер (только
метаданные), TrustMRR (письменное разрешение).

**Reddit и X — решение D43 от 2026-09-08, оно отменяет прежний порядок.**
Основной маршрут для MVP — **сторонний поставщик данных** (Apify Actor или
аналог), а не одобренный Reddit OAuth и не официальный X API: те переведены в
альтернативу и запасной путь. Прежнее условие «сначала одобрение / сначала
оплата тарифа» снято; «по одному за раз» осталось. Основание —
`.autopilot/2026-09-05-idea-scout--wip/reddit_x_idea_scout_handoff.md`, §2, §14,
§15.

Решение **не** объявляет сбор разрешённым. Условия X запрещают scraping «in any
form, for any purpose», Reddit требует explicit approval, и посредник ничего из
этого не меняет — пользователь принял риск письменно. Паспорт это и говорит:
исход `принят под риск` — отдельное пятое значение, а не «разрешён» и не
«выключен». Основной код к конкретному поставщику не привязан: один класс
`Source` на юридический маршрут (`reddit_apify`, `reddit_official`, `x_apify`,
`x_official`), общий формат наружу — существующий `RawItem`, смена актора внутри
маршрута — ключ конфига.

**Снято из активного плана (решения D01–D02 в манифесте):** HTML-сбор Indie
Hackers, Acquire.com и Flippa. Условия этих площадок запрещают сам сбор, ради
которого писались адаптеры, — посредник этого не меняет, и решение D43 на них
**не** распространяется. Паспорта и разбор структуры сохранены как
доказательство и как задел; **фикстура не означает разрешённого сбора**, а
`config/selectors.yml` в этой сборке не создаётся.

### Четыре правила, которые держат это вместе

1. **Поиск — не право на содержимое.** Находка поискового провайдера транзитна:
   в базу, в лог и в промпт модели она не попадает. Сохраняется след запроса;
   документ берётся только через разрешённый канал. Граница — `discovery`,
   не `sources`.
2. **Сигнал — не метрика.** Звёзды, скачивания, просмотры, голоса и взносы это
   `SignalObservation`, а не `MetricClaim`. В выручку не переводятся никогда.
   Цена в листинге при продаже бизнеса — тоже не выручка.
3. **Атрибуция переживает всё.** Где источник её требует, автор, ссылка и
   лицензия доходят до экрана и до экспорта через нормализацию, дедупликацию
   и слияние идей.
4. **Выключенный источник не звонит.** Не «пустой результат» — вызова не
   происходит вообще. Устаревшая дата проверки условий блокирует сбор
   по расписанию. Ноль вызовов дают исходы `не подтверждён` и `выключен`;
   `принят под риск` (D44) к ним **не** относится — это осознанно
   включённый источник, и правило от этого не размывается.

## Две среды: Claude Code и Codex

Разработка идёт в двух средах одновременно, и роли **не** симметричны.

| Среда | Роль | Что можно |
|---|---|---|
| **Claude Code** | оркестратор и контролёр | вести сборку, нарезать и раздавать таски, ревью, коммиты, писать в `.autopilot/` |
| **Codex** | исполнитель отдельных тасков | код в своей зоне, тесты, `docs/` своего таска |

Четыре правила, которые держат это вместе:

1. **В `.autopilot/` пишет только оркестратор**, и это же касается `AGENTS.md`
   и `docs/executor.md`. Исполнитель читает свой таск, `interfaces.md`,
   `spec.md`, `manifest.md`, сам `AGENTS.md` и `docs/executor.md` — и не
   меняет ни один из них. Два процесса, пишущих `state.js`, затирают друг
   друга молча.
2. **Одна рабочая копия — один исполнитель.** Волна из четырёх тасков не
   означает четыре агента в одном дереве. Параллельно — только через отдельные
   git-worktree, иначе они дерутся за индекс. **Worktree создаёт и удаляет
   только оркестратор** — исполнитель получает готовый путь и в нём работает,
   `git worktree add/remove` не его команда.
3. **Зона таска — граница ответственности.** Файл вне своей зоны не трогается
   даже ради одной строки: это `BLOCKED` и разговор с оркестратором. То же —
   если для работы нужно изменить контракт (`interfaces.md`) или выйти за
   пределы зоны: не самостоятельная правка, а `BLOCKED` с указанием, чего не
   хватает.
4. **Коммит, merge и ветки — не дело исполнителя.** Codex не делает
   `git commit`, `git merge`, не заводит и не переключает ветки. Готовый код
   остаётся в рабочей копии; коммитит и сливает оркестратор после проверки.

### Мост к Codex — настройка закреплена 2026-09-06

Прошлый самодельный мост (`claude-codex-bridge`) удалён: его `codex_implement`
жёстко передавал `--full-auto`, снятый в codex-cli 0.153.2, и вдобавок
возобновлял чужую сохранённую сессию. Взамен — официальный плагин
`openai-codex/codex` для Claude Code.

1. **Мост проверен живым вызовом, не на словах.** `codex-companion.mjs task`
   создаёт тред и печатает его id (пример: `01a0766b-35ed-7480-998a-6692d97496e7`),
   код возврата — `0`. Дозапрос через `--resume-last` явно логирует
   `Resuming thread <тот же id>` и учитывает результат первого хода —
   продолжение подтверждено, а не новая сессия.
2. **Базовая модель исполнителя — Terra High.** `.codex/config.toml`:
   `model = "gpt-5.6-terra"`, `model_reasoning_effort = "high"`.
3. **Правило эскалации.** После двух circles ремонта, провалившихся **по вине
   реализации** (не по вине контракта), таск поднимается на Sol High. Возврат
   `BLOCKED` по дефекту контракта неудачным циклом не считается — в таске 03
   все три `BLOCKED` были дефектами контракта (D05–D07), и эскалации не было.
4. **Astra — только по явному подтверждению пользователя** на конкретный
   запуск; сама по себе не берётся ни на исполнение, ни на ревью.
5. **Worktree — обязателен для параллели, но не через `isolation: "worktree"`
   инструмента Agent.** Правило 2 выше («одна рабочая копия — один
   исполнитель») держится механически: волна из нескольких тасков идёт как
   несколько git-worktree, по одному на исполнителя. В прошлом прогоне это
   было нарушено (таски 03 и 16 столкнулись на фикстурах в одном дереве) —
   потерь не было, но так больше не делаем.

   **Найдено 2026-09-06:** `isolation: "worktree"` у Agent создаёт свою
   worktree, но `codex-rescue` при длинной задаче уходит в фоновый джоб и
   сам ход агента завершается мгновенно — инструмент в этот момент видит
   «изменений нет» и подчищает worktree раньше, чем фоновый процесс Codex
   успевает написать код. Все три таска волны 2 первым заходом вернули
   BLOCKED «worktree отсутствует» — кода никто не терял, агенты корректно
   отказались писать вне зоны, но заход впустую. **Правильная схема:**
   worktree создаёт оркестратор сам (`git worktree add`, вне механизма
   Agent-изоляции — такую копию инструмент не трогает), путь называется
   явно в промпте кодекс-агенту первой строкой.
6. **Границы копируются в каждый промпт дословно, а не подразумеваются.**
   Codex не читает этот файл сам — он видит только то, что ему передано в
   задаче. Перед текстом таска в промпт кодекс-агента всегда идёт блок:

   > Твоя зона: `<путь из тикета>`. Правила: пишешь только внутри зоны;
   > не трогаешь `.autopilot/`, `interfaces.md`, `manifest.md`, `spec.md`,
   > `AGENTS.md`, `docs/executor.md`; не делаешь `git commit`/`merge`/ветки;
   > не создаёшь и не удаляешь worktree. Нужно выйти за зону или изменить
   > контракт — верни `BLOCKED` с одной строкой, чего не хватает, и не
   > исправляй это сам.

## Как здесь работает Autopilot

Сборка ведётся навыком `/autopilot`. Правило, которое не отменяется:
**требование из `manifest.md` может снять только пользователь.**

Работа продолжается — скажи «продолжи автопилот»: состояние поднимется
из `.autopilot/state.js`, переспрашивать ничего не нужно.
Прогресс — `.autopilot/dashboard.html`.
