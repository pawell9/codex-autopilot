# Спецификация: Idea Scout

> Редакция 2 от 2026-09-06. Первая редакция переписана после независимого
> архитектурного ревью (`astra-architecture-review.md`); что принято, что урезано
> и что отклонено — в `review-log.md`. Ни одно требование манифеста при этом
> не снято.

## Задача

Человек хочет делать небольшие продукты, которые уже доказали, что работают —
и переносить их на рынок РФ/СНГ. Проблема не в отсутствии идей, а в том, что
подтверждённые кейсы разбросаны по десятку площадок, перемешаны с самопиаром без
единой цифры, повторяются между источниками и устаревают. Ручной обход этих
площадок съедает вечер и даёт три идеи, из которых две он уже видел.

Нужен инструмент, который делает этот обход сам, отбрасывает шум **не удаляя его**,
и кладёт результат в одно место, где идею можно за минуту оценить, отложить,
отклонить — или сразу превратить в рабочий проект.

## Решение

Локальная система из трёх частей.

**Сбор.** По расписанию обходит источники, **сразу записывает найденное на диск**
и только потом фильтрует и оценивает. Всё, что записано, остаётся: фильтр
определяет приоритет и причину, а не существование находки.

**Дашборд.** Локальное веб-приложение: плотный список идей, как в Linear.
Превью в строке, полное досье — по клику сбоку. Фильтры по уровню, теме, уровню
доверия и статусу. Статус ставит человек: новая / в избранном / отклонена /
взята в работу. Алгоритм не удаляет и не отсеивает ничего — только ранжирует
и объясняет, показывая, на чём основана каждая цифра.

**Переход в работу.** Кнопка «взять в работу» создаёт рядом папку проекта:
`AGENTS.md`, `CLAUDE.md`, `.gitignore`, журнал решений, файл состояния и досье
идеи, превращённое в готовый бриф. И открывает её в VS Code. Структура одинаково
читается Claude Code, Codex и OpenCode, так что при исчерпании лимита одного
агента работа продолжается в другом без пересказа контекста.

## Четыре независимых измерения состояния

Спецификация опирается на то, что это **разные** признаки и ни один не выводится
из другого. Смешение любых двух — источник почти всех потерь и ложных выводов.

| Измерение | Значения | Кто меняет |
|---|---|---|
| Решение человека | `new` / `favorite` / `rejected` / `in_work` | только человек (R24) |
| Обработка | `pending` / `running` / `succeeded` / `failed`, отдельно по типу работы | обработчик очереди |
| Классификация | `scope: solo/team/unknown`, архивность, причина низкого приоритета | код и оценка |
| Исследование аналогов | не проверяли / проверили и не нашли / нашли N; ошибка и неполный поиск — отдельно | `dossier` |

## Решения по реализации

### Стек

**Python 3.11+.** Парсеры (httpx + selectolax), оценка (subprocess к CLI),
веб (FastAPI + Jinja + один JS-файл), база (SQLite через `sqlite3`, без ORM).
Скрейпинг и вызов CLI — родная территория Python; второй язык ради фронтенда
стоил бы отдельной сборки, которой в «небольшом несложном дашборде» быть не должно.

**Фронтенд без сборщика.** Одна страница, ванильный JS, CSS без препроцессора.
Причина не в том, что сборка обязательно сломается, а в том, что для одного
экрана она не окупается. Зависимости Python и версии CLI фиксируются;
JS можно позже разложить на модули без сборщика.

**Владение схемой — один модуль.** SQL не размазывается по `pipeline` и `web`:
явные транзакции, внешние ключи включены, уникальные ограничения, индексы под
реальные фильтры, нумерованные миграции с блокировкой и проверкой версии.

### Конвейер: две возобновляемые части, а не одна линия

```
сбор:      источник → страница → [SQLite: сырьё + связи + курсор] → нормализация,
                                  доказательства, дедуп, приоритет → [SQLite: работы]
обработка: [работы] → один обработчик с контролем бюджета → оценка | аналоги
                                                          → [SQLite: результаты]
```

**Принятый от источника элемент не существует только в памяти до ответа модели.**
Сохранение страницы и продвижение курсора имеют согласованную границу фиксации.
HTTP- и LLM-вызовы выполняются **вне** открытой SQL-транзакции; захват работы и
фиксация результата — короткие транзакции.

`prefilter` (возраст, ключевые слова, наличие числа, чёрный список) не решает,
существует ли находка: он ставит приоритет и `not_scored_reason`. Архив,
`scope`, статус человека и результат фильтра — независимы (см. таблицу состояний).

**Очередь — одна таблица в SQLite, один активный обработчик дорогих действий.**
Типы работ `score` и `dossier` раздельны. У работы: объект, тип, уникальный ключ
(объект + тип + версия входа), состояние, попытки, `next_attempt_at`, причина
ошибки, захват обработчиком. Прерванная работа возвращается на повтор по правилу;
ручной и плановый запуск делят общую блокировку. Ровно один внешний вызов при
падении между ответом и записью не гарантируется — достаточно идемпотентной
записи и ограниченных повторов, повторный расход отражается в учёте.

### Источники — паспорт до адаптера

**Ни один адаптер не пишется, пока у источника нет паспорта:** способ и
допустимость доступа, endpoint или actor ID, поля метрик, курсор и правила
пагинации, лимит запросов и результатов, цена, условия хранения и передачи текста
модели, образец реальных данных, поведение при недоступности. Наличие токена — не
то же самое, что разрешённый сценарий. Автоматический переход с API на скрейпер
не является способом обойти ограничение доступа.

**TrustMRR выключен до письменного разрешения (G09).** Условия §9.3 запрещают
и продукты, помогающие копировать найденные бизнесы, и подачу данных API в
оценочные и рекомендательные системы без предварительного письменного согласия.
Пользователь запрашивает разрешение; до ответа адаптер не реализуется и источник
выключен. Требование R10 при этом не снято.

**Паспорт фиксирует не только техническую возможность.** В нём обязательны:
способ получения, режим содержимого, разрешённое назначение и коммерческий
статус, лицензия и атрибуция, срок хранения, обязанность синхронизировать
удаление, допустимость передачи модели, ссылка на условия и **дата, когда
условия читались**. Устаревшая дата проверки блокирует сбор по расписанию —
это проверка, а не напоминание.

**Состав источников определяется классами сигналов, а не списком площадок
(D01–D03).** Шесть классов: `проблема`, `запуск`, `внедрение`, `внимание`,
`деньги`, `финансирование`. Приёмка R10 — не меньше трёх классов из нескольких
независимых семейств каналов. Восемь исходных площадок были описанием способа;
четыре из них запрещают наш сценарий собственными условиями, и обход этих
условий не является способом выполнить требование.

### Разрешённый состав MVP — ноль долларов, ноль ключей

| Источник | Способ | Классы сигналов | Что даёт |
|---|---|---|---|
| **Hacker News** | Algolia Search API + Firebase, без ключа | проблема, запуск | Show HN, месячные треды, жалобы и запросы |
| **Product Hunt** | **официальный Atom-фид**, без токена | запуск | поток запусков; GraphQL — опция только под поля, которых в фиде нет |
| **GitHub** | REST + Search API, 5000 запросов/час | внедрение, проблема | issues и discussions как боль; звёзды как внедрение |
| **Stack Exchange** | официальный API, 10 000 запросов/сутки с ключом | проблема | повторяющиеся вопросы = повторяющаяся боль |
| **Курируемые RSS/Atom** | фиды блогов, чейнджлогов, рассылок основателей | проблема, запуск, деньги | фид — заявленный самим автором канал публикации |

Product Hunt меняет способ доступа с GraphQL на Atom намеренно: фид не требует
токена, не ограничен некоммерческим использованием так, как API, и снимает
контрактную зависимость. Взамен он даёт меньше полей — это осознанный размен.

**Безопасное умолчание по хранению для фидов и публикаций:** метаданные,
короткая цитата, канонический URL, время и производные признаки. Полная
перепубликация текста правами фида не покрывается.

**Stack Exchange лицензирован CC BY-SA.** Автор, ссылка и лицензия обязаны
пережить нормализацию, дедупликацию и любой экспорт. Атрибуция, потерянная
по дороге, — это нарушение, а не косметический дефект.

### Условные источники — по одному за раз (пересмотрено решением D43)

| Источник | Условие старта |
|---|---|
| **Reddit** | **основной маршрут — сторонний поставщик данных** (Apify Actor или аналог) по решению пользователя D43; официальный одобренный OAuth — альтернатива и запасной путь. Минимальное хранение обязательно на любом маршруте. Удаление по требованию: на официальном канале это требование условий Reddit, на стороннем — сигнала об удалении может не быть вовсе, и это ограничение называется в паспорте, а не обходится молчанием. **Отложен решением D54** (2026-09-09): таск 17 в этом заходе Reddit не реализует, паспорт остаётся в исходе «снят» (D01), не `принят под риск`. **Не зависимость MVP:** GummySearch закрылся 30 ноября 2025 года, не получив коммерческую лицензию — рабочая технология не создаёт устойчивого права |
| **X / Twitter** | **основной маршрут — сторонний поставщик данных** по решению пользователя D43; официальный API (pay-per-use, жёсткий потолок расходов) — альтернатива и запасной путь, в этом заходе таска 17 без кода и без credentials. Условия X сбор запрещают, паспорт это фиксирует дословно, и исход паспорта — `принят под риск`, а не «разрешён». **Провайдер зафиксирован решением D54** (2026-09-09, по итогам ресёрча): Apify, актор `xquik/x-tweet-scraper`, целевой объём до 10 000 постов/месяц. Альтернатива по классу сигналов — Bluesky, отдельным паспортом |
| **Search-провайдер** | Tavily или Exa, **только режим метаданных**, после отдельного паспорта. Brave на базовом плане непригоден: его условия запрещают хранение результатов |
| **TrustMRR** | письменное разрешение (G09). До ответа выключен, адаптер не пишется |

**Что именно принял на себя пользователь.** Решение D43 не переоценивает
условия площадок и не объявляет сбор разрешённым. Оно принимает риск: сторонний
поставщик разрешения от имени площадки не выдаёт, малый объём запретов не
отменяет, и площадка сохраняет право на технические и юридические меры. Поэтому
исход `принят под риск` — отдельное значение паспорта, видимое в `doctor` и в
дашборде, а не тихо выставленное «разрешён».

**Маршрут — это отдельный источник, а не настройка внутри одного.** Официальный
канал и сторонний поставщик — разные юридические режимы, значит разные паспорта,
значит разные классы `Source` (`reddit_apify`, `reddit_official`, `x_apify`,
`x_official`). Наружу оба маршрута отдают один и тот же `RawItem`, поэтому смена
поставщика не переписывает систему. Смена конкретного актора внутри маршрута —
ключ конфига, не правка кода.

### Снято из активного плана

Собственные HTML-парсеры Indie Hackers, Acquire.com и Flippa. Причина —
условия площадок запрещают сам сбор, ради которого эти адаптеры писались.
Разбор их структуры сохранён в паспортах таска 02 как задел на случай
письменного разрешения и помечен так, чтобы **фикстуру не приняли за
разрешённый сбор**. `config/selectors.yml` в этой сборке не создаётся.

Апифай-маршрут к X был снят здесь же решением D01 и **возвращён решением
пользователя D43** (2026-09-08) — вместе с Reddit и только для этих двух
площадок. Основание D01 при этом не отменено: условия X по-прежнему запрещают
сбор, изменилась не оценка права, а готовность пользователя нести риск. На
Indie Hackers, Acquire.com и Flippa решение D43 не распространяется.

Замены по классам сигналов: боль Indie Hackers → Stack Exchange, GitHub issues,
Hacker News, фиды авторов; деньги Acquire и Flippa → добровольные раскрытия
основателей, публичные платёжные дашборды. **Цена в листинге не является
выручкой, а взносы не являются MRR** — это разные классы, и складывать их в
один нельзя.

**Open Collective из замен выведен решением D48** (пользователь, 2026-09-08):
его условия требуют prior written consent на сторонние приложения — тот же
случай, что TrustMRR. Разрешение не запрашивается, источник не используется,
и **класс сигналов «финансирование» в этой сборке остаётся незакрытым**.
Приёмка R10 от этого не страдает: она требует не меньше трёх классов, а
подтверждены три — внедрение, проблема, внимание.

### Поиск — это обнаружение, а не право на содержимое (D04)

Search API отвечает на вопрос «где появился релевантный документ», но не даёт
права скачать и бессрочно хранить найденную страницу. Поэтому провайдер поиска
**не реализует обычный `Source`**: у него своя граница.

Порядок: запрос → транзитная находка → проверка политики источника → либо
сохранить только разрешённые метаданные и URL, либо получить документ через
разрешённый канал, либо оставить ссылку на ручную проверку. Сохраняются запрос,
метаданные запуска и разрешённые производные счётчики; запрещённое содержимое
не сохраняется никогда — ни в базу, ни в лог.

Это не отмена Истории 7. Правило «найденное записывается на диск до фильтра и
до модели» продолжает действовать для всего, что **разрешено** сохранять;
там, где сохранять запрещено, требование выполняется сохранением следа —
запроса, ссылки и происхождения, — а не текста.

**Охват измеряется, а не подразумевается.** У каждого источника считается
полезность за период: сколько элементов принесён, сколько прошло фильтр,
сколько дошло до уровня A или B, сколько человек отправил в избранное.
Отчёт после сбора печатает эти числа по источникам — это и есть та сторона
соотношения «охват / стоимость», которую иначе не с чем сравнить. Бесконечного
backfill нет: у источника окно повторного чтения и потолок элементов за запуск.

**Дешёвые API-модели не оцениваются, потому что условие не наступило.**
Пользователь просил это оценить «если такой возможности нету» — возможность
платить подпиской есть (`claude -p`, `codex exec`). Если разрешение или лимиты
однажды сделают подписочный путь непригодным, сравнение глубины API-моделей
становится отдельной задачей, а не молчаливым переключением.

**Уровень `verified` без TrustMRR — одно правило и никаких вторых.**
`verified` = ссылка на самопубликуемый платёжный дашборд продукта (публичная
страница Stripe/LemonSqueezy/Polar, которую владелец опубликовал сам).
Листинг с раскрытой финансовой отчётностью — это `proof`, **не** `verified`:
раскрытие продавцом при продаже бизнеса и подтверждение платёжной системой —
разные вещи. Всё остальное — `proof` или `claimed`.

**Результат сбора — не голый список.** `FetchResult` содержит элементы, курсор,
признак полноты, предупреждения, расходы и исход источника. Пустой результат
и сломанный источник — разные исходы. Курсор продвигается **после** сохранения
соответствующих данных.

### Доказательства метрик

Каждое утверждение о метрике — отдельная запись:

```
MetricClaim: kind, value, unit_or_currency, period, observed_at,
             source_item_id, evidence_locator, evidence_excerpt,
             trust_level, extraction_method
```

`evidence_locator` — путь поля в сохранённом ответе API или фрагмент снимка
текста. Сумма без валюты или периода остаётся неоднозначной и молча не
превращается в MRR. Диапазоны вида «$10k+» сохраняются как диапазоны.
Конфликтующие утверждения хранятся раздельно. Уровень доверия принадлежит
**метрике и её периоду**, а не продукту целиком.

Модель предлагает извлечённое утверждение со ссылкой на доказательство;
`scoring` работает с принятыми фактами и не меняет их. Даже совпадающая цитата
не делает утверждение автора истинным — различие `claimed / proof / verified`
именно об этом.

**Сигнал — не метрика, и одно в другое не переводится.** Звёзды GitHub,
скачивания npm и PyPI, просмотры страниц, объём поиска, голоса на Product Hunt,
взносы Open Collective — это `SignalObservation` со своим классом и своим
происхождением, а не `MetricClaim`. Они дают охват там, где денежные метрики
недоступны, и участвуют в оси «доказанность» — но **не превращаются в MRR,
выручку или число платящих ни при каких обстоятельствах**.

Практическое следствие: у идеи может не быть ни одной денежной метрики и при
этом быть три независимых сигнала внедрения. Это честное состояние, а не
пробел, и в карточке оно так и выглядит — «денег не подтверждено, внедрение
подтверждено трижды», а не выдуманная цифра.

### Полномочия CLI — два режима, зафиксированные флагами

Проверено локально на установленных CLI:

| Режим | Claude | Codex | Граница |
|---|---|---|---|
| Оценка | `-p`, `--tools ""`, `--restricted`, `--strict-mcp-config`, `--permission-prompts none`, `--json-schema`, `--settings` (свой), рабочий каталог отдельный | `exec`, `--sandbox read-only`, `-C <пустой каталог>`, `--output-schema`, `-c shell_environment_policy.inherit=none` | никаких инструментов чтения файлов, записи, shell, MCP и веба |
| Поиск аналогов | тот же изолированный каталог, разрешён только веб-поиск/чтение | **отключён в V1 (D59):** `read-only` не запрещает shell/file read | нет выполнения команд, нет доступа к проектам и секретам |

`--allowedTools` управляет автоодобрением, а не составом инструментов; состав
задаётся `--tools`/`--restricted`. Конфигурация каждого адаптера проверяется
испытанием, а не выводится из названия флага. Валидация JSON происходит **после**
работы агента и сама по себе ничего не предотвращает — поэтому границу задают
флаги, а не схема.

**Внешний текст никогда не становится инструкцией, путём, конфигурацией или
командой.** В `docs/brief.md` досье уходит в явно размеченный блок внешних
данных; доверенные `AGENTS.md` и шаблоны собираются только из шаблонов
приложения. Логи провайдеров редактируются перед записью, чтобы не сохранить
секреты.

### Бюджет

**Формула: $20–30 в месяц — это расходы сверх уже оплаченных подписок**
Claude и ChatGPT. Подписки в сумму не входят; отсутствие отдельного счёта
не делает подписочный ресурс бесконечным, поэтому у CLI есть лимиты
длительности, объёма входа, числа попыток и веб-исследований.

**MVP не тратит ничего.** Hacker News, Product Hunt Atom, GitHub, Stack Exchange
и курируемые RSS бесплатны и не требуют ключей. Потолок $20–30 сохраняется —
он не израсходован, а не потрачен, и это разные вещи.

Лимиты — в конфиге, журнал расходов и резервов — в SQLite. Перед платным
действием атомарно резервируется максимально разрешённый расход; после
завершения резерв сверяется с фактом. Платному запуску передаётся потолок на
стороне провайдера, если провайдер это умеет; хранится удалённый идентификатор
запуска, чтобы после таймаута наблюдать за уже запущенной работой, а не
создавать вторую. При неизвестном исходе второй платный запуск не создаётся
автоматически. **Протокол резерва не зависит от провайдера** — он написан под
отсутствие ключа идемпотентности, а это свойство есть и у X API.

**Расценки условных источников — снимок 2026-09-08/09, не вечная истина.**
Официальный X API, чтение постов — $0.005 за ресурс, pay-per-use; на пользовательском
доступе (не Enterprise) поиск ограничен окном 7 дней. Ресёрч таска 17 (§13 handoff)
проведён оркестратором до старта: актёр Apify **`xquik/x-tweet-scraper`** — $0.15
за 1000 результатов, на целевом объёме до 10 000 постов/месяц это около $1.5,
против $25–50/мес у официального X API на том же объёме. Reddit-сторону ресёрча
таск 17 в этот заход не использует — маршрут отложен решением D54.
Тариф и баланс принадлежат аккаунту: локальный флаг включает уже реализованный
адаптер, но не покупает тариф и не создаёт отсутствующую интеграцию.

Протокол резерва от смены маршрута не меняется. Он написан под отсутствие ключа
идемпотентности, и это по-прежнему верно: у стороннего поставщика роль удалённого
идентификатора запуска играет идентификатор запуска актора, у X API такого якоря
нет вовсе. Потолок расходов передаётся на сторону провайдера там, где провайдер
это умеет; не умеет — записывается в паспорт, и потолок держится нашей стороной
(R09.2).

Платный адаптер остаётся выключенным; переполнение очереди его не включает.
**Reddit и X одновременно не подключаются** — иначе нельзя понять, что именно
дало прирост и что именно съело бюджет.

### Идентичность и дедупликация

`Idea` в первой версии — **конкретный исходный продукт**; публикации и
доказательства связываются с ним. Нормализация идентичности и правила
объединения живут в одном доменном модуле; `store` обеспечивает сохранение
и ограничения.

- Точное совпадение устойчивого ID источника или проверенного URL — автоприсоединение.
- Домен — дополнительный сигнал, с исключениями для общих платформ.
- Нечёткое совпадение имени — **кандидат** на объединение, не слияние;
  отказ пользователя на нечёткого кандидата не переносится.
- Основание связи и исходные элементы сохраняются, чтобы ошибку можно было
  исправить.
- Неизвестный продукт — отдельный кандидат, а не угаданная идентичность.

### Скор

Рубрика с примерами для каждой оси: что означают 3, 6 и 9, и что означает
«нет данных» — это не ноль. Веса по умолчанию: переносимость 0.35,
подтверждённость 0.30, простота 0.25, размер 0.10. Уровень A ≥ 7.5, B ≥ 5.5,
иначе C. **Веса и уровень вычисляются в коде**; `level`, вернувшийся от модели,
не принимается. Смена весов не требует вызова модели.

`Score` содержит: оси с обоснованиями, тема (основная + опциональная вторая),
блокеры, **`scope: solo/team/unknown`**, версии модели, промпта, профиля,
рубрики и входных доказательств, время. Пересчёт по новому профилю трогает
только зависящую от профиля часть; старый результат живёт до успешного нового.

**Три даты не смешиваются:** дата публикации, дата показателя, дата обнаружения.
Неизвестная дата не подменяется текущей.

**Тема-теги — закрытый список из семи:** `бот`, `расширение`, `SaaS`,
`агентская система`, `API-сервис`, `микроинструмент`, `прочее`. «Инфопродукт»
исключён: он противоречит выбранному целевому классу «софт» (расхождение
с манифестом исправлено в манифесте).

**Блокеры — закрытый список:** `платёжка`, `юрисдикция`, `локальный рынок`,
`язык`, `интеграция`, `данные`. Вид плюс строка пояснения.

**Порция на разбор (G08): цель — 10–20 идей в неделю на разбор.**
Показываются верхние N ещё не разобранных карточек, `N` в конфиге,
по умолчанию 3 в день. Если за неделю в разбор попало заметно меньше или
больше — крутится порог скора и `N`, а не отбрасываются идеи. Остальные всегда
доступны фильтром; автоматического удаления и скрытого отбора «навсегда» нет.

### Поиск аналогов

`dossier` не имеет своего поисковика: он формирует запросы и отдаёт их
CLI-провайдеру в режиме поиска. Возвращается **отчёт исследования**: запросы,
время, реально использованные URL, краткое основание сходства, статус полноты
или ошибки. Отсутствие веб-поиска или его ошибка не превращаются в
`checked_not_found`. В интерфейсе — «по выполненным запросам аналоги не найдены»,
формулировки «ниша свободна» нет. У исследования свой бюджет и ограничение числа
финалистов; вручную выбранную идею можно послать на исследование мимо порога.

### Локальный HTTP и создание проекта

Сервер слушает loopback, проверяет допустимые Host и Origin, не меняет состояние
через GET, защищает изменяющие запросы локальным непредсказуемым токеном и не
разрешает произвольный CORS. Текст источников экранируется; для ссылок
допускается только белый список схем.

Генератор умеет три операции: `create_dir`, `write_new_file`, `open_editor`.
Каждая гонит путь через единственный вход:

```python
def safe_path(root: Path, candidate: str) -> Path:
    """Единственный вход для любого пути."""
    if not candidate or Path(candidate).is_absolute():
        raise UnsafePath(candidate)          # пустой и абсолютный запрещены
    if ".." in Path(candidate).parts:
        raise UnsafePath(candidate)
    p = (root / candidate).resolve()
    if not p.is_relative_to(root.resolve()):
        raise UnsafePath(candidate)
    return p
```

Первая редакция принимала абсолютный путь внутри `root` и возвращала сам `root`
на пустой строке — это расходилось с заявленной приёмкой. Корень фиксирован
конфигом; набор относительных путей шаблона неизменяем и не приходит извне.
`resolve()` — проверка на момент времени: создание файлов не следует за
симлинками. Конкурирующий локальный злоумышленник в модель угроз не входит —
модель угроз здесь: враждебный текст из интернета и ошибка в коде.

Операций удаления и перемещения в модуле **нет** — не «запрещены проверкой»,
а не написаны. Существующая папка не перезаписывается: возвращается ошибка
и предложенное имя с суффиксом, решает человек. VS Code открывается
`subprocess.run(["code", str(path)], shell=False)`, `code` найден через
`shutil.which`; если не найден — путь показывается для копирования. Слаг папки
собирается по белому списку `[a-z0-9-]`, ≤48 символов.

**Идемпотентность:** у операции есть идентификатор и связь `idea_id → project_path`;
повтор завершённой или partial-операции возвращает тот же проект и сохранённую диагностику ошибки
(D60). Открытие редактора —
отдельный исход, независимый от записи файлов. Статус «взята в работу» не
появляется при неуспешном создании.

### Передача работы между агентами

`.state.json` версии формата 1: текущая цель и этап, завершённое, следующий
конкретный шаг, результаты проверок, блокеры, ссылки на решения, состояние
рабочей копии или commit. Обновляется на смысловых границах и перед передачей;
новый агент **сверяет запись с файлами**, а не считает её безусловно актуальной.
По умолчанию одну рабочую копию меняет один агент.

**Про «параллельно вести разработку».** Структура поддерживает два сценария:
последовательный — упёрся в лимит, открыл другой агент, он поднимает контекст
из `.state.json` и журнала; и параллельный — два агента работают над **разными**
проектами или разными рабочими копиями одного, каждый со своим файлом состояния.
Чего эта версия не делает: два агента одновременно в одной рабочей копии —
они затрут правки друг друга, и файловое состояние от этого не спасает.
Если нужен именно этот режим, он требует отдельного решения (рабочие ветки
или worktree) и в текущий объём не входит.

Ручное переключение — решение о границах этой версии, а не утверждение о
невозможности в принципе. Совместимость чтения инструкций Claude Code, Codex
и OpenCode проверяется на минимальном проекте: одна строка `См. @AGENTS.md`
приёмкой не является.

### Эксплуатация

1. **Воспроизводимый запуск.** Абсолютные пути к Python и CLI, рабочая
   директория, явная загрузка конфига и `.env` для launchd. CLI живут внутри
   каталогов версий Node — их наличие в интерактивном PATH не гарантирует запуск
   планировщиком.
2. **Сон и выключение.** `StartCalendarInterval` догоняет пропущенный запуск
   после сна, но не после выключения. Ожидание сформулировано именно так;
   сбор восстанавливается с курсора.
3. **SQLite под несколькими процессами.** `serve`, сбор и обработка могут идти
   одновременно: короткие транзакции, `busy_timeout` с повтором, включённые
   внешние ключи, согласованный режим журнала. Миграции — с блокировкой
   и проверкой версии.
4. **Резервное копирование.** База хранит отказы, избранное, доказательства
   и очередь. Способ согласованного backup/restore зафиксирован; копирование
   активного файла без учёта режима журнала процедурой не считается.
5. **Срок хранения сырья.** Политика удержания по источнику. Карточка, решение
   человека и отметка о недоступности доказательства остаются всегда.
   Где политика конфликтует с A02, уступает A02 — это добавка, не требование.
6. **Ограничение входа.** Максимальный размер ответа, таймауты, правила
   перенаправлений, белый список URL. Данные загружаются только через
   конкретные адаптеры источников — сервер не разыменовывает произвольные URL
   из постов.
7. **Видимость состояния.** Источники, очередь, расход, последняя успешная
   обработка, частичные результаты и ошибки создания проекта видны пользователю.
   Время сброса лимита доходит до `jobs.next_attempt_at` без замены локальным backoff (D61).
   Отчёт за месяц считает сигнал только по его точно связанному raw-item и `fetched_at`, не по совпадению source (D62).
8. **Рост объёма.** Серверная пагинация и индексы; десятки тысяч карточек
   со снимками не выгружаются на одну страницу, досье грузится по запросу.

**Что исполнителю разрешено читать.** Свой таск, `spec.md`, `interfaces.md`
и `manifest.md` — читать можно и нужно; менять их нельзя. Остальное содержимое
`.autopilot/` исполнителю не нужно и частью проекта не является.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `sources` | добычей **разрешённого** сырья | `Source.fetch(state: SourceState) -> FetchResult`, `Source.policy -> SourcePolicy`, `REGISTRY` | HTTP, авторизацию, пагинацию, разбор фидов |
| `discovery` | обнаружением через поиск, **без права хранить найденное** | `DiscoveryProvider.search(query, budget) -> DiscoveryResult` (транзитные находки, расход, исход), `policy_gate(hit) -> Allowed \| UrlOnly \| Refused` | запросы провайдера, разбор выдачи, потолок расходов |
| `identity` | тем, что считается одним продуктом | `resolve(item) -> IdeaRef \| Candidate`, `merge(a, b, reason)` | канонизацию URL, правила домена, нечёткое сравнение |
| `evidence` | утверждениями о метриках и их доверием | `extract(item) -> list[MetricClaim]`, `accept(claim) -> AcceptedMetric` | разбор чисел, периодов, валют, конфликтов |
| `queue` | работами и их жизненным циклом | `enqueue(kind, obj, key)`, `claim() -> Job \| None`, `complete(job, result)` | захват, попытки, `next_attempt_at`, блокировки |
| `budget` | деньгами и резервами | `reserve(kind, max_usd) -> Reservation`, `settle(res, actual, run_id)` | журнал, расчётный период, потолки |
| `llm` | доступом к модели и переключением | `LLMProvider.complete(prompt, schema, mode) -> Completion` (исход, данные, расход, провайдер, длительность, опц. время повтора), `chain_from_config(cfg)` | флаги изоляции, вызов CLI, разбор ошибок |
| `scoring` | осями, уровнем, темой, блокерами, `scope` | `score(idea, accepted_metrics, profile, llm) -> Score` | промпт, рубрику; **веса и уровень считает `scoring`, не модель** |
| `dossier` | исследованием аналогов | `find_analogues(idea, llm) -> ResearchReport` (состояние, запросы, URL, находки) | запросы, разбор выдачи |
| `store` | схемой, сохранением и ограничениями | `save_raw`, `upsert_idea`, `list_ideas(filters, page)`, `set_status`, `get_idea` | SQL, миграции, транзакции |
| `scaffold` | созданием проекта на диске | `create_project(idea, cfg, op_id) -> ProjectResult` (запись и открытие редактора — раздельные исходы) | шаблоны, `safe_path` |
| `web` | HTTP, страницей и защитой запросов | приложение FastAPI | маршруты, шаблоны, токен, экранирование |

**Швы для тестов — три, все уже в таблице:**

- `LLMProvider.complete` — фейк; через него проверяются `scoring` и `dossier`.
- `Source.fetch` — записанные фикстуры; через него проверяется весь конвейер.
- `DiscoveryProvider.search` — фейк; через него проверяется, что транзитная
  находка **не доезжает до диска**.

**Проверки соответствия условиям — это тесты, а не документация.** Их пять,
и они обязательны: выключенный источник делает ноль сетевых вызовов;
транзитное содержимое не попадает ни в SQLite, ни в лог; атрибуция переживает
нормализацию и экспорт; устаревшая дата проверки условий блокирует сбор по
расписанию; у платного источника есть жёсткий потолок расходов.

Остальное тестируется как есть: `store` и `queue` — на временном SQLite,
`scaffold` — на временной директории, `budget` — на журнале. Фейки не проверяют
разрешение доступа к API, реальную форму ошибок CLI, качество извлечения и
запуск под launchd — для этого нужны отдельные небольшие интеграционные проверки.

## Приёмочные сценарии, которые должны пройти

| Область | Сценарий |
|---|---|
| Сохранность | Остановка процесса после сохранения страницы, во время оценки и перед фиксацией ответа; перезапуск не теряет находок, статусов человека и границ расхода, не создаёт дублей карточек |
| Полномочия CLI | Обычный JSON-ответ; отсутствие логина; лимит первого и обоих провайдеров; таймаут; невалидная схема; отказ веб-поиска; **враждебная инструкция в тексте источника** |
| Доказательства | ARR не становится MRR; цена продажи не становится выручкой; установки не становятся MAU; неподтверждённая метрика не наследует чужой `verified` |
| Бюджет | Остаток меньше стоимости следующего запуска; два конкурентных запуска; потерянный HTTP-ответ; переход расчётного периода; платный fallback выключен |
| Идентичность | Одинаковые имена разных продуктов; общий домен платформы; повтор URL; публикация о нескольких продуктах; совпадение с ранее отклонённой идеей |
| Генерация и HTTP | Двойной клик; существующая папка; пустой и абсолютный путь; симлинк; ошибка `code`; чужой Origin; HTML и опасная схема URL в тексте источника |
| Качество отбора | Небольшой заранее размеченный набор: разные типы продуктов, старые кейсы, отсутствующие метрики, дубли, скриншоты. Сравнить фильтр и двух провайдеров по расходу и полезности верхних 10–20 |

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| R36i — работа на VPS | решено начать локально. Проектное решение: конвейер без macOS-зависимостей, пути из конфига, `serve` принимает `--host/--port`. Проверяется отдельным прогоном, а не объявляется сделанным. При переносе останется: интерактивный логин CLI на сервере, перенос SQLite, launchd → cron, закрытие дашборда снаружи, и **удалённый `code <path>` не откроет локальный VS Code** — понадобится другой адаптер |
| R30 — автопереключение агентов внутри разработки | решение о границах этой версии: переключение ручное, состояние файловое (R31) |
| Сбор с Indie Hackers, Acquire.com и Flippa | **снято из активного плана (D01, D02):** условия этих площадок запрещают наш сценарий. Ни собственный парсер, ни сторонний актор, ни любой третий способ это не меняет. Разбор структуры сохранён в паспортах; вернётся вместе с письменным разрешением, отдельным таском. **X из этой строки выведен решением D43** — не потому, что его условия изменились, а потому что риск по нему принят пользователем письменно |
| Лицензированные поставщики данных (Brandwatch и подобные) | закрывают охват договором, а не обходом условий, но это корпоративные цены. Путь к коммерческой версии, если покрытие Reddit и X станет критичным — не для этой сборки |
| Common Crawl как источник | открытый корпус не отменяет прав издателей, дорог по вычислениям и несвеж — плохой источник для MVP |
| TrustMRR как источник API | выключен до письменного разрешения (G09); **решением D46 закрыт для MVP** — запрос не отправляется. Требование R10 не снято |
| Реализация адаптера `anthropic_api` (A01) | интерфейс есть, адаптер откладывается — добавка без доказанной необходимости |
| Разделение прав записи между извлечением и приёмкой фактов | второй проверяющий агент для инструмента с одним пользователем; модель доказательств внедряется, разделение прав — нет |
| Аккаунты, логины, шаринг | «Только я» |
| Автообновление метрик у собранных идей | исходный срез с явной датой; новая публикация с другой цифрой — дополнительное утверждение, не перезапись |
