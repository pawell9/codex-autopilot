## Что должно заработать

Ни один адаптер нельзя писать вслепую. Этот таск не пишет адаптеров — он
выясняет, что вообще возможно, и оставляет после себя восемь паспортов
и записанные образцы реальных данных, на которых потом строятся фикстуры.

Паспорт на каждый источник: способ доступа, допустимость **нашего** сценария
по условиям площадки, endpoint или actor ID, поля метрик, правила пагинации
и курсора, лимиты запросов и результатов, цена, условия хранения и передачи
текста модели, поведение при недоступности, образец ответа.

**Наличие токена — не то же самое, что разрешённый сценарий.** Условия читаются
и цитируются, а не пересказываются.

## Критерии приёмки

- [ ] Восемь файлов `docs/sources/<имя>.md` по единому шаблону
- [ ] У каждого — цитата из условий площадки про допустимость нашего сценария, со ссылкой
- [ ] Для X выбран конкретный Apify-актор: ID, входная схема, цена за результат, ограничение глубины истории, образец вывода
- [ ] Для трёх витрин — конкретные публичные маршруты и подтверждение, что нужные показатели вообще видны без авторизации
- [ ] Для Hacker News — конкретные запросы Algolia, а не «мы будем искать»
- [ ] Записанные образцы ответов в `tests/fixtures/<источник>/` — то, на чём потом строятся тесты
- [ ] Список имён переменных возвращается **в артефакте паспорта**; сам `.env.example` не трогается (его владелец — таск 01)
- [ ] У каждого паспорта проставлен исход: `разрешён` / `разрешён с оговоркой` / `не подтверждён`, и условие старта интеграции
- [ ] Отрицательный исход одного паспорта не блокирует источники с положительным — это записано явно
- [ ] TrustMRR: паспорт фиксирует запрет из §9.3 и статус «выключен до письменного разрешения»
- [ ] Источник, для которого доступ не подтвердился, помечен явно — не выдаётся за готовый
