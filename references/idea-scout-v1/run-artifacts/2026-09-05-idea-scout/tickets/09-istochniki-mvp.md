## Что должно заработать

Четыре разрешённых источника поверх протокола из таска 07. Все бесплатны,
ни один не требует ключа для запуска. Вместе с Hacker News из таска 07 это
и есть весь MVP-охват: пять каналов, четыре класса сигналов, ноль долларов.

| Источник | Способ | Классы сигналов |
|---|---|---|
| Product Hunt | **официальный Atom-фид**, без токена | запуск |
| GitHub | REST + Search API, 5000 запросов/час | внедрение, проблема |
| Stack Exchange | официальный API, 10 000 запросов/сутки с ключом | проблема |
| Курируемые RSS/Atom | фиды блогов, чейнджлогов, рассылок основателей | проблема, запуск, деньги |

**Product Hunt идёт через Atom, а не GraphQL** — это решение спецификации,
а не упущение. Фид не требует токена и не ограничен некоммерческим
использованием так, как API. Меньше полей — осознанный размен. Лезть в GraphQL
за недостающими полями можно только после отдельного паспорта.

**Reddit в этом таске нет.** Он стал условным источником и живёт в таске 17.

Список фидов — конфиг, а не код: `config/feeds.yml`, владелец — этот таск.
Добавление фида не требует правки Python.

**Канал регистрации уже есть — решение D17.** Один RSS-модуль объявляет N
источников (по записи `feeds.yml`, у каждой свой `source = "rss:<id>"`) через
`SOURCES: dict[str, SourceFactory]` вместо одиночного `SOURCE`; `discover()`
принимает оба вида в одном обходе. Прочитай раздел «Расширение контракта от
2026-09-06 — множественная регистрация источника (D17)» в `interfaces.md`
до кода — это ровно то место, где раньше был канал только на один источник
за модуль. Как читать `feeds.yml` (путь, формат, устаревание проверки прав)
и как строить N фабрик со статичной `.policy` каждая — решает этот таск сам,
контракт этого не предписывает.

## Критерии приёмки

- [ ] Каждый источник объявляет `SourcePolicy`, значения перенесены из паспорта T16 дословно
- [ ] Product Hunt читает **Atom**; GraphQL не вызывается ни разу
- [ ] GitHub: search по репозиториям, issues и discussions; учтён лимит 1000 результатов на запрос
- [ ] Stack Exchange: работает без ключа, с ключом — расширенная квота; отсутствие ключа не ошибка
- [ ] **Атрибуция Stack Exchange (CC BY-SA) заполнена у каждой записи**: автор, ссылка, лицензия
- [ ] RSS: список фидов в `config/feeds.yml`; неотвечающий фид не роняет остальные
- [ ] Хранится метаданные, короткая цитата, канонический URL и время — **не полная перепубликация текста**
- [ ] Все возвращают `FetchResult` с корректным исходом; исчерпание лимита — отдельный исход, не ошибка
- [ ] Отсутствующий ключ даёт исход «нужна настройка», а не падение и не пустой список
- [ ] Общие ограничения загрузки из таска 07 переиспользуются, а не переписываются
- [ ] Тесты на фикстурах таска 16; в сеть не ходит ни один
- [ ] Проверки соответствия 1–3 из §Политика тестов контракта пройдены
- [ ] Источник без паспорта не реализуется — это `BLOCKED`, а не догадка по документации
- [ ] Ни один ключ не попадает в лог или сообщение об ошибке
- [ ] `pytest -m real`: малый реальный сбор по каждому источнику

## Долг из таска 07 — внесено оркестратором 2026-09-06

Вертикальный срез сдал Hacker News с доказанной сохранностью, но не с полным
охватом. Полнота этого источника — твоя.

- [ ] **Комментарии треда.** Паспорт прямо говорит: «Тексты постов Show HN
      часто содержат метрику не в самом посте, а в комментарии автора»,
      и добираются они вторым запросом `search?tags=comment,story_<ID>` —
      это отдельный `RawItem` с тем же `story_id`, не склейка на этапе добычи.
      Из «Способа доступа» не реализован также `items/<ID>`. **Для R04 по этому
      источнику это главный незакрытый кусок:** сейчас собираются посты, а
      деньги называются в комментариях.
- [ ] **Сверка цитат условий с живой страницей.** Паспорт помечает свои цитаты
      документации Algolia как снятые из JS-бандла SPA и требует сверки при
      первом реальном прогоне. Поправка 4 сняла эту оговорку частично: поведение
      `search_by_date`, пагинация и потолок подтверждены живьём. Цитаты условий
      (YC legal, «no rate limit», 10 000 запросов в час) — **не сверены**.
- [ ] **Квота не кратна размеру страницы.** Потолок 1000 делится поровну
      (250 на поток при четырёх активных), страница просится по 100 и не
      делится: поток берёт 100 + 100, на третий запрос получает 100 при остатке
      50 и **выбрасывает всю страницу**. Потери нет — граница не сдвинута, —
      но из потолка используется 800, и на каждый поток приходится впустую
      потраченный запрос за прогон. Строку паспорта §«Окно и потолок» про число
      запросов поправить тем же решением.
- [ ] **Поток без прогресса не эскалирует.** Если страница отдаёт элементы, но
      ни одной допустимой отметки времени, граница не двигается, поток снова
      уходит в работу, и следующий прогон читает то же окно — вечный `partial`
      с кодом 0 и без нарастающей тревоги. У Hacker News отметка есть всегда,
      но **этот шаблон не копируй в новые источники**: считай прогоны без
      сдвига границы и после нескольких подряд поднимай исход до `error`.

**Что переиспользовать, а не переписывать.** `sources/http.py` — общие
ограничения загрузки; `Source`/`SourcePolicy`/`REGISTRY` — протокол и обход
подпакетов; правило «позиция курсора никогда не выше непрочитанных данных» —
оно выведено дорого, пятью кругами, и относится ко всем источникам, а не
только к Hacker News.
