## Что должно заработать

Оценка идёт через подписочные CLI, а не через API. Упёрся в лимит Claude —
очередь уходит в Codex; упёрлись оба — работы ждут, ничего не теряя.

**Главное в этом таске — не переключение, а границы полномочий.** Через
провайдера проходит недоверенный текст из интернета, а `claude` и `codex` —
это агентские среды с инструментами. Режим оценки не должен иметь инструментов
вообще.

Флаги проверены на установленных CLI:

**Схема передаётся двум CLI по-разному** — проверено на установленных версиях:
Claude принимает `--json-schema '<сама JSON-схема строкой>'`, Codex принимает
`--output-schema <путь к файлу>`. Не перепутать.

| Режим | Claude Code | Codex |
|---|---|---|
| Оценка | `-p --tools "" --restricted --strict-mcp-config --permission-prompts none --json-schema '<схема>' --settings <свой> --add-dir <пустой каталог>` | `exec --sandbox read-only --skip-git-repo-check --ephemeral -C <пустой каталог> --output-schema <файл> -c shell_environment_policy.inherit=none --strict-config` |
| Поиск аналогов | то же, но `--tools "WebSearch,WebFetch"` вместо `""` | то же, плюс включённый веб-инструмент конфигом |

**Асимметрия провайдеров реальна, и её нельзя заминать.** У Claude `--tools ""`
действительно снимает весь набор инструментов. У Codex `--sandbox read-only` —
это политика **выполнения сгенерированных моделью shell-команд**, а не
отсутствие инструмента: аналога `--tools ""` в `codex exec` нет.

Значит: если провайдер не может дать требуемые полномочия для режима, адаптер
возвращает `unsupported_mode`, и цепочка идёт дальше. **`read-only` не выдаётся
за «инструментов нет».** Молча подменять подписочный путь платным API нельзя.

`--allowedTools` управляет автоодобрением, а не составом — состав задаётся
`--tools`/`--restricted`. Валидация JSON происходит **после** работы агента
и сама по себе ничего не предотвращает: границу задают флаги, а не схема.

Интерфейс `anthropic_api` (A01) объявляется, адаптер **не реализуется**.

## Критерии приёмки

- [ ] `complete()` возвращает нормализованный исход: `ok`, `rate_limited(until?)`, `unavailable`, `invalid_schema`, `timeout`, `auth_error` — различены, не свалены в один
- [ ] Лимит первого провайдера переводит работу на второй; лимит обоих оставляет работу в очереди
- [ ] Время сброса показывается, **только если провайдер его сообщил**; иначе поле пустое, а не выдуманное
- [ ] Режим оценки запускается с флагами из таблицы; проверено, что процесс стартует именно с ними
- [ ] Провайдер, не способный дать полномочия режима, возвращает `unsupported_mode`, а не выполняет запрос с более широкими правами
- [ ] Для режима `research` возвращаются `tools_used` и `pages_read`; **один URL, написанный моделью в JSON, доказательством чтения не считается**
- [ ] Зафиксированы проверенные версии обоих CLI; несовпадение версии — предупреждение в `doctor`, а не тихая работа
- [ ] Автономные тесты проверяют сборку аргументов, разбор исходов и переключение — на фейке процесса
- [ ] **Отдельная проверка `pytest -m real`:** реальный запуск обоих CLI в обоих режимах на подготовленном враждебном тексте; проверяется, что инструменты вне разрешённого набора не вызывались и файлы не изменились. Фейк `complete` эту границу не испытывает и не заменяет
- [ ] Рабочий каталог провайдера изолирован и не содержит проекта, `.env` и `.autopilot/`
- [ ] Таймаут завершает дочерний процесс, а не оставляет его висеть
- [ ] Ответ, не подходящий под схему, даёт одну повторную попытку, затем `invalid_schema`
- [ ] stderr и ответы провайдера редактируются перед логированием — тест, что ключ из окружения не попал в лог
- [ ] Возвращаются провайдер, длительность и расход/usage
- [ ] Ни один тест не зовёт реальную модель
