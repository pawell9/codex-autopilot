# Codex Autopilot v1.0.4 lifecycle audit

Date: 2026-09-16
Baseline: v1.0.3 (`274a9e3`)
Audited history: v1.0.0 `8f79007`, v1.0.1 `266f8ec`, v1.0.2 `7bb4007`, v1.0.3 `274a9e3`
Release compatibility floor: ledger schema `1.0`, creation release v1.0.0

## Outcome

The v1.0.3 state machine was not lifecycle-complete. The reported Idea Scout
criteria dead end was one instance of a wider class: records and validators
existed without complete publication, termination, repair, retry, and
currentness paths. v1.0.4 closes the identified paths without rewriting
legacy provenance or immutable history.

The corrected model is machine-readable in `design/lifecycle-model.json`.
Reachability and mutation tests prove that the required G0–G6 success edges
are present and necessary, and that every represented nonterminal local state
has an outgoing transition. The realistic offline qualification reaches
`ACCEPT/ACCEPTED`; the exact Idea Scout migration/V5 sequence reaches revision
31 on a disposable copy without changing source bytes.

## Evidence and version reconstruction

The Git tags establish the helper release sequence above. The Idea Scout
ledger's `skill_version: 1.0.0` is creation provenance, not evidence that later
mutations used only v1.0.0. Snapshot reasons match the missing capabilities
introduced in v1.0.1–v1.0.3. Because old ledgers did not record effective
helper versions, v1.0.4 does not invent retrospective migration entries.
Instead, the first v1.0.4 mutation adds `runtime_provenance` with:

- immutable `creation_skill_version` copied from legacy `skill_version`;
- `current_schema_version`;
- `last_mutating_skill_version`;
- `compatibility_floor`;
- explicit, hash-bound `applied_migrations` from that point onward.

Unknown schemas are reported by `diagnose` in read-only mode. They are never
coerced into schema 1.0.

## Run transition model

Normal success is uniquely reachable through:

`PREFLIGHT/ACTIVE → INTENT/ACTIVE → DESIGN/BLOCKED → DESIGN/ACTIVE → PLAN/ACTIVE → EXECUTE/ACTIVE → VERIFY/ACTIVE → ACCEPT/ACTIVE → ACCEPT/ACCEPTED`.

The DESIGN/BLOCKED step is conditional for legacy requirements adoption; a
new fully populated run may remain DESIGN/ACTIVE. Required guard evidence:

| Edge | Atomic authority | Guard/evidence |
|---|---|---|
| G0 PREFLIGHT→INTENT | `publish-intent`, `gate` | owner/revision, capability and target reconciliation, immutable intent |
| G1 INTENT→DESIGN | `gate` | current intent and resolved product authority |
| REQ DESIGN self-route | `adopt-requirements` | exact intent binding, complete bidirectional requirement/criterion links |
| G2 DESIGN→PLAN | `gate` | current publication coverage PASS, no current blocker |
| G3 PLAN→EXECUTE | `gate` | current coverage and plan PASS; current tickets PLANNED/READY |
| G4 EXECUTE→VERIFY | `gate` | all current tickets INTEGRATED, leases/effects closed, no blocker |
| G5 VERIFY→ACCEPT | `prepare-handoff`, `import-manual`, `gate` | exact candidate/current intent, complete receipts and current PASS |
| G6 ACCEPT→ACCEPTED | `gate` | fresh G5 PASS remains current; no blockers, live leases, or unresolved effects |

Legal backwards edges are evidence-classified: PLAN/BLOCKED→DESIGN for design
repair; VERIFY/ACCEPT BLOCKED→EXECUTE for implementation repair;
EXECUTE/VERIFY/ACCEPT BLOCKED→DESIGN for contract repair; and any later
blocked phase→INTENT for authorized intent repair. Other phase jumps fail.

Control transitions are independent of phase. ACTIVE/BLOCKED/RECOVERING may
enter QUIESCING; PAUSED requires QUIESCING plus stopped attempts, released
leases, and reconciled effects. PAUSED/BLOCKED resume through RECOVERING.
FAILED and CANCELLED require quiesced terminalization. Terminal controls are
immutable. Epoch takeover quarantines all PREPARED/DISPATCHED leases and
fences old packets/returns.

## Local machines

| Machine | Normal path | Alternative terminal/recovery paths |
|---|---|---|
| Ticket | PLANNED→READY→RUNNING→CANDIDATE→REVIEW→INTEGRATED | BLOCKED→READY; REVIEW→REPAIR→READY; affected states→STALE; scoped termination→CANCELLED |
| Attempt | PREPARED→DISPATCHED→RETURNED | PREPARED/DISPATCHED→INTERRUPTED; DISPATCHED→LOST |
| Lease | active→released | active→quarantined→released |
| Operation | prepared→applied | prepared→uncertain→applied/abandoned; prepared→abandoned |
| Design publication | PUBLISHED→SUPERSEDED | amendment may also produce INVALIDATED; replacement is a new immutable PUBLISHED record |
| Requirements publication | PUBLISHED→INVALIDATED | amendment invalidates authority; later intent requires a new explicit publication |
| Verdict | PENDING→PASS/BLOCK/UNVERIFIABLE | verdict immutable; authority can be invalidated/superseded, never edited |

## Identity model

The following revisions are deliberately not interchangeable:

1. `packet_registration_revision`: ledger observed when the packet is
   registered;
2. `packet_source_revision`: immutable value copied into the return;
3. `subject_revision`: publication/candidate revision being reviewed;
4. `attempt_created_revision`: ledger revision produced by registration;
5. `return_source_revision`: packet source observed in the accepted return;
6. current ingest revision: optimistic concurrency fence for the mutation.

The state-bound validator checks all six where applicable. Structural schema
validation only checks shape. Finding refs may name packet-local axes/checks;
ingest maps them to the canonical subject while retaining
`reported_affected_refs` for forensic fidelity.

## Crash and fault matrix

| Window | Durable observation | Safe recovery |
|---|---|---|
| Before object write | no new object or ledger ref | retry normally |
| Object written, ledger not published | orphan hash-addressed object | exact retry adopts it; conflicting bytes reject |
| Canonical doc installed, ledger not published | same-byte orphan document | exact retry validates/adopts; differing bytes block |
| Ledger published, response lost | revision already advanced | exact command detects current identical record and returns idempotently |
| Publication committed, reviewer not registered | current publication + durable next action | register fresh attempt; never reuse old verdict |
| Packet registered, spawn unknown | PREPARED + active lease | recovery proves no spawn then INTERRUPTED/release, or quarantine until liveness known |
| Return temp written, rename absent | no authoritative return | producer may finish rename if still authorized; otherwise terminate/recover |
| Return renamed, ingest absent | exact inbox bytes | stop producer, state-bound validate, ingest once |
| Ingest committed, response lost | RETURNED + return hash + released reviewer lease | same-hash retry is zero-effect |
| Git effect prepared, command outcome unknown | operation `prepared`/`uncertain` | reconcile base/tree/receipt; never blindly repeat |
| Commit exists, candidate receipt absent | Git object plus prepared operation | verify exact receipt and publish candidate once |
| Review PASS, integration publication interrupted | immutable return/integrity evidence | exact integrate reconciles or publishes once; candidate must match |
| Current ledger corrupt | `ledger.prev.json`/verified snapshots | `recover` selects newest valid source and records provenance; no guessed rewrite |
| Unknown schema | readable envelope only | `diagnose` read-only; install compatible migration before any mutation |

## Invariants checked

- No execution entry without current G2 coverage and G3 plan PASS.
- No current ticket readiness before all dependencies are reviewed INTEGRATED.
- No INTEGRATED ticket without exact candidate review PASS and integrity
  receipt.
- No ACCEPTED run without a fresh current-intent G5 PASS.
- No terminal success with a blocking current issue, active/quarantined lease,
  or prepared/uncertain effect.
- No historical verdict satisfies a new fingerprint or intent.
- No cross-kind reviewer disagreement.
- No RETURNED reviewer retains an active lease in v1.0.4-authored state.
- No accepted return can pass state preflight and then fail ingest solely from
  a different interpretation of identity/axes/references.
- No same-input retry creates a second externally meaningful record/effect.
- No requirements migration edits V5 or infers authority from prose.

## Residual limitations

- Schema 1.0 is the compatibility floor. Unknown schemas need a separately
  reviewed migration and remain read-only.
- Filesystem atomicity and advisory locking rely on the local filesystem's
  documented semantics; process liveness still requires observable stop
  evidence or quarantine.
- Critical/G5 reviewer isolation remains the documented user-assisted
  clean-session protocol; receipts prove declared observable boundaries, not
  unobservable host internals.
- Runtime provenance begins when a capable helper first mutates a legacy run;
  it cannot cryptographically reconstruct helper versions that old releases
  never recorded.
