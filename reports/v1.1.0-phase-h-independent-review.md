## Verdict

**BLOCK.** H-01 through H-05 remain closed, and the latest commits materially
improve Q03 and Q35. The release package is current and honest about native
runtime support. Two canonical qualification gaps remain, however:

1. Q35 now has a real public repair/preserve chain and exact persisted
   provenance assertions, but it directly edits and rewrites the ledger after
   `init`/bootstrap. This violates the required “public CLI only after
   bootstrap” qualification boundary and makes the fixture state partly
   fabricated rather than a public transition chain.
2. Q03 now executes one continuous preserve → two repair authorizations →
   final qualification/integration chain, but it exercises only one path
   (`app-one.txt`) and does not assert per-path origin preservation across an
   untouched-file hop or the durable repair provenance for both repair
   attempts. The canonical Q03 assertion explicitly requires those origins.

These are test/qualification gaps; product code was not modified by this
review. Do not release v1.1.0 or resume R58 on this evidence.

## Blocking findings

### H-06 — Q35 still mutates canonical ledger state after bootstrap

The improvement in `f924c59` is real: Q35 now dispatches a repair worker,
ingests its BLOCK return, creates a candidate commit, invokes public
`preserve-blocked-candidate`, and asserts durable `repair_lease_provenance`,
source attempt, candidate SHA/base, finding, authorization, expanded lease,
lineage, receipt, and parent links (`tests/test_phase_h_boundaries_v110.py`:
`740–808`). The former fabricated provenance fallback is gone. The focused
Q35 test passes.

The scenario is still not a valid independent public-CLI qualification. After
`run("init", ...)` at line 629, it loads and manually replaces tickets and
lifecycle state, sets revision/previous hash/repository metadata, validates,
and writes the canonical ledger directly at lines `634–649`; it then calls
`install_execution_design` and directly rewrites `repository.initial_head`
and the ledger again at lines `651–654`. The test itself acknowledges this as
“fixture setup,” but it occurs after the ledger bootstrap and bypasses the
public owner/CAS-fenced transitions. Removing those writes leaves no ticket or
valid current design for the subsequent public chain, so the test is
self-confirming about its starting state.

This is the exact gap called out by the reliability audit's qualification
minimum: public CLI only after bootstrap, with no manual pointer edits. It
also conflicts with the master plan's prohibition on manual ledger editing.

**Required action:** construct the ticket, design publication, repository
binding, and readiness preconditions through the public CLI (or move all
fixture construction before the actual bootstrap boundary); do not call
`ledger.atomic_write` on the canonical ledger after `init`. Keep the current
repair/preserve provenance assertions and rerun Q35.

### H-07 — Q03 chain is continuous, but canonical per-path provenance remains unqualified

The improvement in `17ceee1` closes the prior one-repair/one-hop defect. The
current Q03 uses public `q.mutate`, `q.change_review`, `q.worker_candidate`,
and `integrate` calls in one fixture (`tests/test_phase_h_qualification_matrix_v110.py`:
`355–455`). It has a real HANDOFF preserve hop, two candidate-bound repair
authorizations (`Q03-AUTH-1`, `Q03-AUTH-2`), two repair workers, a fresh PASS
qualification, exact finding/blocker resolution, projection checks, released
leases, and qualified integration. The current focused test passes in
33.134s.

The canonical Q03 matrix assertion is stronger: “Per-path origins survive
untouched-file hops; no scalar `current_attempt` loss.” This implementation
uses only `app-one.txt` for the preserve and both repairs (helper lines
`190–223`, scenario lines `378` and `397`), so it never has an untouched
second path whose origin must survive the chain. It also checks parent
candidate and authorization IDs but does not assert the durable
`repair_lease_provenance`/lineage records for Q03-W2 and Q03-W3 themselves.
Q35's create-only fixture covers one provenance shape, but cannot substitute
for Q03's own per-path continuous-chain assertion.

**Required action:** make Q03 use at least two in-scope paths, leave one path
untouched on a repair/preserve hop, and assert each path's durable origin,
source attempt, base/candidate, authorization, finding, and lineage through
both repairs and final integration. Preserve the current no-manual-pointer
and finding-projection assertions, then rerun the full Q01–Q24 matrix.

## Residual release risk and disposition

Product resolution, replay, ownership/liveness, release parity, and R58
copy-only protections are materially stronger and currently green. The
remaining risk is qualification credibility: one canonical scenario starts
from directly rewritten ledger state, and another does not test the matrix's
per-path untouched-file provenance invariant. Green tests cannot close those
gaps. Fix only the qualification scenarios, rerun current focused tests plus
the complete Q01–Q42/orchestrator suite, and repeat this independent review
before any v1.1.0 release or R58 resume.
