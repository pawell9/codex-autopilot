## Remaining blocking findings

### H-06 — Q35 is still partial and self-confirming

`tests/test_phase_h_boundaries_v110.py:617-681` performs a review finding,
authorization, and repair dispatch, but not the required complete review →
worker → preserve provenance chain. There is no repair worker return,
candidate publication, or subsequent preserve hop; the only continuation was
preserved before the review/repair and is merely inspected afterward.

More seriously, lines 666-672 use:

```python
provenance = repair_attempt.get("repair_lease_provenance") or {
    "source_attempt_ref": "A-1", ...
}
```

That fallback fabricates the durable fact Q35 is meant to prove. The test
passes even if the product omits `repair_lease_provenance` entirely on the
compact lease path. It cannot establish the canonical source-review,
worker, preserve-hop invariant.

**Required action:** remove the fallback, require persisted provenance, and
execute a real repair return/candidate followed by a preserve hop. Assert the
source attempt, parent candidate, finding, authorization, base, and receipt
links from durable state.

### H-07 — Q03 still does not execute “several repairs including preserve hops”

`tests/test_phase_h_qualification_matrix_v110.py:198-216` calls
`V104Qualification.execute()`, which creates one blocked candidate, one repair
authorization, one repaired candidate, and one fresh review/integration. It
asserts two candidates and one consumed authorization, then invokes the old
one-hop normalization unit test as a separate fixture. It does not execute
several sequential repairs over one continuous candidate chain, and does not
integrate a chain containing preserve hops. Q28 now covers its own two-repair
path, but that does not make canonical Q03 truthful.

**Required action:** make Q03 run at least two sequential repairs and a
preserve hop in one fixture, then assert every parent/provenance link and final
integration state.
